# SDK 短预推荐设计

## 目标

在输入法候选栏中提供 SDK 自有的短文本预推荐，同时保留草稿面板承载长文本、多条回复和多联系人内容。推荐项由 SDK 统一持有，宿主可推送或由内置 AI 结果转换为推荐项；输入法负责展示和写入当前输入框。

## 边界

- 推荐项最多六条，每条包含稳定标识、展示文本和可选来源标签。
- 推荐项只允许用户明确点击后写入当前输入框，不自动发送、不模拟点击、不执行搜索跳转或 CPA 重定向。
- 写入使用当前编辑器快照和 SDK 已有的安全写回接口；只有用户已开启编辑器上下文时才读取，快照缺失或过期时拒绝写入并保留推荐项。
- 推荐项只保存在进程内，不进入本地草稿存储，不携带聊天记录、联系人身份或 API 密钥。
- 草稿继续使用现有红色删除、绿色新增、重试和确认写回流程。

## 组件与数据流

1. `SuggestionController` 维护去重、数量上限、选中项和清空操作，并暴露只读状态流。
2. `TrimeSdk.suggestions` 作为宿主和内置模块的统一入口。
3. 输入法候选栏订阅状态流；Rime 候选为空且存在短推荐时显示紧凑按钮，点击时在主线程获取当前快照并调用 `requestEditorCommand(CommitText(...))`。
4. 写回成功后清除当前推荐，失败不改变状态，并给用户明确反馈。
5. 长文本和多条内容仍由 `DraftController` 独占展示权；两个控制器互不依赖。

## 失败处理与测试

- 单元测试覆盖空文本、重复标识、长度上限、清空、选择和状态替换。
- 写回逻辑复用既有编辑器命令测试，确保不可读字段、密码字段、过期快照和非主线程调用均拒绝。
- 资源与主题检查确认候选栏在默认主题和宿主主题合并后仍可加载。
- 设备测试增加短推荐出现、点击写入以及写回失败后仍可重试的场景。
