# SDK 键盘布局 API 设计

## 目标

把主题中的常用键盘布局提升为稳定 SDK 类型，使宿主可以请求九宫拼音、26 键、英文、数字、电话、日期时间、符号、编辑、五笔和笔画布局，同时不依赖主题内部的按键命令字符串。

## 边界

- `KeyboardLayout` 只描述稳定布局标识，不暴露 `KeyboardWindow`、View 或 Rime 对象。
- 请求必须在主线程执行；输入法服务未创建、主题不包含目标布局或布局标识未知时返回 `false`。
- 请求失败不改变 `current`；切换成功后由实际输入法窗口发布当前布局。
- 宿主不能通过该接口绕过系统启用/选择输入法，也不改变方案词库、编辑器权限或发送行为。
- 仍保留主题内部的临时布局和字段类型自动路由；公开请求只是显式覆盖当前输入框的布局。

## 数据流与测试

1. `TrimeSdk.keyboardLayouts` 暴露控制器，`supportedKeyboardLayouts()` 和 `requestKeyboardLayout(...)` 提供清单与请求入口。
2. `TrimeInputMethodService` 挂载布局请求处理器，委托当前 `InputView` 校验并调用 `KeyboardWindow`。
3. `KeyboardWindow` 在实际附加布局后发布状态，输入法销毁时清空状态。
4. 单元测试覆盖稳定标识、主线程边界、未知布局拒绝、旧处理器不能清除新状态。
5. 设备测试覆盖九宫、26 键、数字、符号和编辑布局请求后的真实按键控件。
