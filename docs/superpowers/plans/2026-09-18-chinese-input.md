# 中文输入能力实施计划

目标：独立 App 与宿主 SDK 使用同一套可输入、可切换、可验证的中文方案与键盘。

职责边界：Rime 负责转换和词库；YAML 负责布局及按键映射；输入法前端负责编辑器连接和生命周期；宿主只调用 SDK 接入接口。未来草稿、推荐通过独立接口接入，不写进方案转换规则。

- [x] 核查 SDK 基线、现有方案及设备环境。
- [x] 引入九宫拼音、六套双拼、五笔86资源并记录固定来源。
- [x] 提供常用键盘主题：26键、九宫、数字、符号、编辑、五笔、笔画。
- [x] 接入默认方案、切换和字段类型适配，保留用户自定义配置。
- [x] 增加配置契约及真实 Rime 仪器测试。
- [x] 模拟器安装并验证候选、上屏、退格、切换及屏幕适配。
- [x] 重建独立 App、SDK 和宿主示例，验证发布包接入。
- [x] 完成最终视图复查并更新验证记录。

最终设备验收采用 API 36.1 模拟器原生 x86_64 库；ARM64 转译结果不作为稳定性依据，不将模拟器结果等同于所有物理设备兼容。

## 分层结果

- 方案资源复用 Rime 转换能力，不在布局代码中实现双拼或五笔算法。
- `zhishurufa.trime.yaml` 独立组合已有主题与布局能力，不复制一套 Kotlin 键盘。
- `preserve_ascii_mode` 使编辑布局可保留组合内容；宿主业务由 `ImeHostActionHandler` 接口承接。
- 本地源码依赖与 Maven AAR 依赖两种接入均已构建；同一套 SDK 随宿主安装，并通过系统输入法框架跨 App 工作。
- 修复引擎过早报告就绪的问题：在专用线程等待 Rime 维护结束，避免读配置与词库维护并发。

## 验证边界

354 项 JVM 单元测试通过。设备测试覆盖方案真实候选与上屏、26键触摸、九宫触摸/退格、数字切换、编辑光标、中英文状态保留、横竖屏以及独立测试 APK 接收文字。九宫为候选级消歧，固定音节侧边栏、物理机矩阵、正式签名发布仍未纳入本轮交付。

原生 x86_64 运行的 Maven 发布包接入版本通过八组仪器测试，最新发布包测试为 `OK (8 tests)`；ARM64 转译对照同样为 `OK (8 tests)`。双架构 AAR、两个架构的独立 App APK 和双架构示例 APK 均通过原生库、词库及资源哈希验证。

ARM64 转译曾出现间歇性崩溃，保留在 `build/arm64-emulator-crash.log`，其中一次位于 `native_bridge_malloc`。这一证据尚不能证明物理 ARM64 设备是否受影响，因此 ARM64 本机验收保持未完成；不通过忽略失败或只重试来宣称该路径稳定。
