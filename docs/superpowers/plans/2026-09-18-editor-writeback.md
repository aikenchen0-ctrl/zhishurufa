# 编辑器读写边界

## 问题

<重表述提示词为问题>如何让同一套输入法核心为宿主提供可验证、可拒绝的编辑器上下文与写回能力，同时不引入 AI、推荐、结算和全局监控业务？</重表述提示词为问题>

作用链：宿主明确启用 -> SDK 快照 -> 宿主生成建议 -> 用户确认 -> SDK 校验会话和原文 -> 当前 InputConnection 接受或拒绝编辑。

约束：不保证目标编辑器提供全文或光标矩形；不读取密码；不保留关闭后的快照；不覆盖其他会话；不与正在执行的 Rime 组合输入竞争；不保证跨进程读写原子性。控制与数据由 SDK 承载，模型调用、草稿持久化与消息发送归宿主。

## 当前证据

401 项单元测试通过。干净模拟器曾复现 `onCreateInputView -> getThemeScope -> Required value was null`，已增加主题就绪前占位、就绪后替换逻辑，并避免框架与 SDK 重复挂载同一输入视图。设置页测试改为读取本地化资源并断言实际设置内容。本轮最终 x86_64 冷启动十四项通过（88.329 秒），ARM64 转译十四项通过（91.080 秒），两种 ABI 产物校验通过；AI 工具栏入口、长按菜单防崩溃和流式响应随 Release 构建验证；实体手机与跨进程原子写入仍不是本轮保证。
