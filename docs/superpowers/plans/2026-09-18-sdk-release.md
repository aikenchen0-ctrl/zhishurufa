# SDK 稳定性与发布验证

目标：检查原生线程边界，提供可区分的调试/发布 SDK，验证经压缩的宿主接入。

- [x] 核查现有产物、崩溃日志和设备环境。
- [x] 修复确定的原生线程越界，增加设备回归测试。
- [x] 配置 release AAR 及独立发布坐标，保持旧调试坐标可用。
- [x] 构建双架构发布库，执行代码与资源检查。
- [x] 验证 R8 压缩后的宿主与原生接口。
- [x] 在原生模拟器复跑方案、输入和跨 App 流程。
- [x] 对 ARM64 转译进行有界对照，单独保留未验证项。
- [x] 停止本轮测试进程。

结果：354 项单元测试通过，Release x86_64 与 ARM64 转译各八组设备测试通过；SDK 和独立 App 的两个 ABI 产物哈希、真实词库、原生库检查通过。已修复延时读取线程越界、配置释放后访问、非法候选分配和 SDK 宿主存储冲突。物理 ARM64 验收、历史 SIGSEGV 唯一根因、正式发布签名仍未完成。

保持高内聚低耦合：线程串行化属于 Rime 层；发布与签名属于构建层；宿主业务继续只通过 SDK 公开接口接入。本轮不把缺少真机变成无限重试，也不修改无证据关联的第三方引擎算法。
