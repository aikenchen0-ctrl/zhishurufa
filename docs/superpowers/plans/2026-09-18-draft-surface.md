# 纯 SDK 草稿展示

<重表述提示词为问题>在不依赖 AI、平台跳转、OCR、无障碍或全局悬浮窗的前提下，如何让宿主与输入法复用草稿交互，并且仅在明确确认后写入当前编辑器？</重表述提示词为问题>

## 边界

- 核心：安全编辑器快照/写回、输入法布局/候选/光标/安全区、通用草稿面板、内存选择/版本展示/展示权仲裁。
- 可选 UI 能力：键盘区域内拖动展开、按钮、文本版本标记。全局拍点/边缘手势不能由 IME 保证；不拦截系统返回。
- 宿主：AI/提示词/角色/风格/意图、联系人与多会话归属、商业推荐/深链/CPA、视频商城、OCR/无障碍/跨应用悬浮窗、发送消息。
- 按用户追加要求，SDK 提供可选本地草稿存储；默认仅内存，显式启用后使用私有不备份目录。恢复内容不携带已失效的编辑器会话。
- 绿色勾本轮仅代表写入编辑器，不等于目标 App 已发送。重试只发宿主动作，不伪造 AI 成功。

## 结构

`DraftController` 是纯内存状态，App 与 IME 各自创建控件，不跨窗口搬 View。IME 活跃时占展示权，关闭后回到宿主；多个宿主控件也仅一个可显示。同进程内有效，不承诺多个 App 共用一份草稿。

控件挂在 `InputView.keyboardView` 内、现有输入栏上方，纳入 IME 避让和触摸边界。无草稿不占高度；IME 初始一行，宿主初始约两行半。仅控件拖柄控制草稿区高度，保留键盘按键几何，不实现隐藏系统 IME 后仍驻留屏幕的浮窗。

数据由宿主推送；可传入明确的文本差异片段，红底+删除线表示删除，绿底+下划线表示新增；写入文本必须排除删除片段。生成算法不属于渲染器。写入绑定原始编辑器快照，会话或原文已变化时拒绝，不自动改绑。

## 已知边界

`getExtractedText` 不保证全文；`CursorAnchorInfo` 依赖目标编辑器上报。无障碍字符定位扩展从 API 26 引入，但需目标控件支持；不是 Android 12 后所有应用自动支持。局部 OCR 需要合法截图权限并且存在误差。触摸面积只对当前收到的 MotionEvent 有意义，设备数据可能不完整。草稿本地保存由 `LocalDraftStore` 显式调用，使用不参与系统备份的应用私有目录；不保存联系人、聊天记录或编辑器会话。相关官方参考见本轮职责文档。
